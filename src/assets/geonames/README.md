# GeoNames city dataset

`geonames-cities.json` is a **generated build artifact**, not hand-written
data or application source code — it is committed to the repository so the
running app never needs network access to look up a city (see
`src/common/geo/city-directory.ts`), but it must be regenerated (not
hand-edited) whenever it needs to change.

## Where the data comes from

Generated by `npm run geonames:build`
(`src/common/geo/build/generate-cities-dataset.ts`) from two official
GeoNames export/dump files (CC BY 4.0 —
<https://download.geonames.org/export/dump/readme.txt>):

- [`cities1000.zip`](https://download.geonames.org/export/dump/cities1000.zip) —
  every city with population > 1000, or an administrative seat down to
  PPLA3 (~170k places worldwide). Each row carries GeoNames' own stable
  `geonameid` and a flat `alternatenames` list (untagged by language, but
  sufficient for search — see `city-directory.ts` for why this project
  doesn't need the larger, language-tagged `alternateNamesV2` dataset).
- [`admin1CodesASCII.txt`](https://download.geonames.org/export/dump/admin1CodesASCII.txt) —
  English admin1 (region) names, used once at generation time to resolve
  each city's `region` so the running app never has to.

## How to refresh it

```sh
npm run geonames:build
```

This downloads both files fresh from `download.geonames.org` (a one-time,
manual network fetch — **never** run automatically by `npm install`,
`npm run build`, or app startup, and **never** the GeoNames Web API), parses
them, and overwrites `geonames-cities.json` in place. Commit the result
like any other source change.

## When to run it

There is no fixed schedule. Run it when refreshed place data is actually
wanted (new administrative seats, renamed places, etc.) — GeoNames
republishes these files roughly monthly, so refreshing more often has no
effect. The file already in the repo is fine to leave as-is otherwise.
